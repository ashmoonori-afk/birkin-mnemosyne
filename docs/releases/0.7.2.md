# birkin-mnemosyne 0.7.2

This release fixes same-stem index collisions. Markdown notes in different
folders remain searchable even when they share names such as index.md or
README.md. The core still needs no runtime dependency, embedding model or API key.

## What changed

The newest file keeps the bare filename stem. Every other same-stem file gets
its vault-relative path without .md as a key; a root file uses ./name.
Equal modification times retain the existing lexicographic path tie-break.
Source paths and bytes are unchanged. Index refresh tracks writes, winner
deletion and renames. Existing hidden-file, cache, symlink and archive rules remain.

Only this indexing fix is included. An experimental ranking correction and
taxonomy features are not part of 0.7.2.

## Public round-two measurements

The fixed corpus contains 20,000 public documents, including 6,500 Korean
documents. Existing questions were reused, not regenerated. The primary
heldout endpoint is any-known-gold recall@2: at least one accepted source in the
first two results. Gold includes generator-source documents and alternatives
accepted by existing source-bound evidence. Baseline is main c6a289f.

| Heldout slice | Questions | Baseline hits | Slug-fix hits |
|---|---:|---:|---:|
| Overall | 1,011 | 270 (26.71%) | 537 (53.12%) |
| Korean | 822 | 220 (26.76%) | 407 (49.51%) |
| English | 189 | 50 (26.46%) | 130 (68.78%) |
| At least one gold already indexed | 470 | 270 (57.45%) | 274 (58.30%) |
| All known gold previously dropped | 541 | 0 | 263 (48.61%) |

Overall gain: +26.41 percentage points, with 274 paired gains and seven losses.
Development overall improves from 231/524 to 263/524, but its already-indexed
known-gold slice declines from **231/405 to 224/405** (-1.73 points).
Using only generator-source matches, the already-indexed development slice
declines from 220/399 to 204/399 (-4.01 points). These losses are not hidden by
the overall gain.

Generator-source heldout recall@2 improves from 255/1,011 to 519/1,011.
The closed-discovery sensitivity subset improves from 156/431 to 286/431.
"Closed" means no unresolved alternative in the existing candidate list, not
an exhaustive semantic audit of the corpus.

The index grows from 8,292 to 20,000 notes and from 16.51 MB to 32.70 MB.
One-pass heldout query p50/p95 on Linux are 9.01/21.94 ms before and
28.62/84.55 ms after. These observed times are not a production SLA.

## Statistical limitation and owner decision

The 69 preselected independent source anchors have 28 gains and no losses:
exact two-sided McNemar p=7.450580596923828e-9. The all-case paired p-value is
descriptive because questions share source families.

The preregistered whole-family overall and language confidence intervals were
**not computable**: some language/category strata contain only one independent
source family. That criterion was not passed. On October 15, 2026 at 15:14 KST,
the owner explicitly decided to ship the indexing fix on the paired evidence,
waiving this interval criterion while retaining the engineering release checks.

The question set was reused and ancestor heldout aggregates had already been
seen. Alternative-answer coverage remains incomplete; NONE semantics and
downstream task correctness were not established. These results measure
retrieval, not semantic answer accuracy, universal improvement, or complete
recovery of every previously found note. Only aggregate results from the public
corpus are reported here.

## Install

```sh
python -m pip install "birkin-mnemosyne==0.7.2"
# Optional MCP server:
python -m pip install "birkin-mnemosyne[mcp]==0.7.2"
```

The bundled plugin is 0.2.3 and pins core 0.7.2. Existing installations are not
upgraded automatically.
