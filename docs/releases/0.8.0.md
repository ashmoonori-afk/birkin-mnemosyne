# Release notes v0.8.0

Opt-in cross-language reranking raised recall Hit@5 from 298 to 1,028 of 1,432 unseen questions in six languages (3.45x) when a judge is configured; without one, recall stays local and unchanged.

## What's new

- `KibitzerAdapter.recall()` and the MCP tool `memory_kibitzer_candidates` rerank automatically when `MNEMOSYNE_RERANK_API_KEY` is set or a `decide` client is passed, and report the `selector` used and any `fallback` reason.
- New `KibitzerAdapter.select_crosslingual()` and `birkin_mnemosyne.crosslingual` (`opengateway_decider`, `translate_views`, `RerankError`): candidates from the original and translated queries (BM25 and TF-IDF cosine, top 32 each) are scored by a hosted judge, the best five are kept, then ordered by pairwise comparison.
- `MNEMOSYNE_RERANK_TRANSLATOR` adds English and Korean query views; `MNEMOSYNE_RERANK_TIMEOUT` sets seconds per request.
- Judge requests run up to five at a time, with results kept in input order. `select()`, `search()` and the standard-library core are unchanged and never call a model.

## Measured result

Research harness, October 25, 2026 (PR #91). Hit@5 counts questions with at least one labeled relevant note among the first five candidates. The baseline is the existing local `select()` with `max_items` 5.

| Unseen six-language holdout, 1,432 questions | Baseline | With reranking |
|---|---:|---:|
| Hit@5 | 298 | 1,028 |
| Hit@5, equal-language average | 20.8% | 71.8% |

Ratio 3.45x, grouped 95% interval 3.14-3.81. Every language and its native-language subset passed the preregistered no-decline rule. Before scoring, two source questions whose translations failed the quality check were removed with all their copies (8 cases per arm), leaving 1,432 of 1,440 questions.

The package reproduces the study: replaying all 58,498 saved holdout judge answers through this package's code gave the same five notes in the same order for 1,432 of 1,432 questions, with every request byte-identical. Retrieval itself is not covered by that replay: the package uses its own tokenizer, while the study used the research retrievers.

Known weak spot (PR #90, historical Hit@2 floors on the original cases): on Korean MIRACL (213 questions) the pairwise step lowers the result from 142 to 137, still above the floor of 107. It stays because the method without it failed the SciFact floor (215 against 224 of 300); with it, SciFact scores 231. The earlier 2,400-question result in PR #90 reused questions while the method was chosen, so it is selection evidence only.

## Cost, speed and privacy

- Off unless `MNEMOSYNE_RERANK_API_KEY` is set or a `decide` client is passed. The generic `OPENGATEWAY_API_KEY` does not turn it on.
- Without a key nothing leaves the machine: `recall()` returns the local BM25 ranking and logs one warning per adapter. `MNEMOSYNE_RERANK=off` (also `0`, `false`, `no`) or `recall(rerank=False)` turns it off with no calls and no warning.
- When on, each query sends the query and note excerpts (the note description up to 200 UTF-16 units plus an excerpt of up to 1,500 code points) to the hosted judge, plus two translation requests when a translator is configured.
- Estimated cost: about $0.0081 of judge spend per query on average (token-count estimate from the research harness, not an invoice), plus the translation requests. Estimated latency: about 4 s per query with five requests in flight (from request timings, not an end-to-end measurement).
- A missing key, network error, timeout or malformed response falls back to the local BM25 ranking with one warning, never a partial rerank.
