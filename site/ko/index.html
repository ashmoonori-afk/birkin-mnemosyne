01 / 지도는 항상, 문서는 필요할 때

저장소 전체 대신 필요한 맥락을.

새 세션에는 이전 작업으로 돌아갈 길이 필요합니다. 모든 노트를 처음부터 넣으면 지금 작업과 무관한 내용에도 컨텍스트를 쓰게 됩니다.

검색
INDEX 언제 읽을지 → 어떤 문서인지
프로젝트 노트
디스크 위의 Markdown

시작할 때 완전한 INDEX

선택 기능인 INDEX는 “언제 읽을지 → 어떤 문서인지” 경로를 모두 유지합니다. 큰 지도는 완전한 주제별 보기를 사용할 수 있습니다. 소프트 예산을 넘으면 경고할 뿐, 경로를 조용히 없애지 않습니다.

INDEX 사용 가이드 읽기 ↗

작업에 필요할 때 상세 문서

정확한 트리거로 문서 전체를 엽니다. 작업에 묶인 시작 읽기는 어휘로 일치한 모든 문서를 완전히 반환합니다. 일반 검색은 다국어 BM25, 사용량 기반 감쇠와 구역 우선순위를 씁니다. 어휘 일치는 의미 일치를 보장하지 않습니다.

다음 세션을 위한 인계

프로젝트·작업별 불변 체크포인트에 작업, 결정, 미해결 항목, 질문, 다음 단계와 링크를 남깁니다. 범위가 지정된 시작 읽기는 최신 기록 전체를 포함합니다. MCP 클라이언트는 캡처·재개 호출을 직접 관리하고, Hermes는 선택형 생명주기 콜백을 제공합니다.

라벨과 미리보기부터 시작하는 초기화

읽기 쉬운 namespace:value 라벨은 순위 점수에 들어가지 않고 후보 노트를 필터링합니다. mnemosyne init은 명시적으로 적용하기 전에 정리·가져오기 계획을 보여줍니다. 노트를 자동으로 병합·보관·삭제하지 않습니다.

폴더 구조를 그대로 사용

0.7.1부터 여러 단계로 나뉜 Markdown 폴더도 기본 검색에 포함됩니다. 숨김 파일, 캐시와 링크는 제외합니다. 전체 상대 폴더 경로를 사용하며, 보관과 되돌리기는 원래 하위 경로와 바이트를 유지합니다. 0.7.2는 폴더가 다른 같은 이름의 노트도 모두 검색합니다.

터미널에서 메모 읽기

배포된 패키지의 search, list, show로 메모를 확인할 수 있습니다. 사용 기록을 늘리거나 사용 빈도 순위를 바꾸지 않습니다. 라벨 필터를 반복해서 지정하면 순위 계산이나 페이지 나누기 전에 대상 메모를 좁힙니다.

02 / 측정값과 단서를 함께

검색과 시작 비용,
측정값과 한계.

문서에 공개된 실험 결과입니다. 사용자의 저장소나 에이전트 답변에 대한 보장은 아닙니다.

0.8.0: 다른 언어로 물어도 맞는 노트를 찾게 돕는 재정렬(켰을 때만).

MNEMOSYNE_RERANK_API_KEY를 넣으면 recall()(MCP 도구 memory_kibitzer_candidates 포함)의 후보 순서를 외부 판정 모델이 다시 매겨요. 번역한 질문으로도 찾으려면 MNEMOSYNE_RERANK_TRANSLATOR도 설정해야 해요.

번역 질문을 쓴 연구 환경에서 처음 보는 6개 언어 질문 1,432개 중 정답이 5위 안에 든 질문이 298개에서 1,028개로 늘었어요(3.45배, 2026년 10월 25일 측정, PR #91). 키만 넣은 구성은 측정하지 않았어요.

질문 하나에 약 0.0081달러와 약 4초가 드는 것으로 추정되고, 키가 없거나 MNEMOSYNE_RERANK=off면 지금처럼 내 컴퓨터 안에서만 돌아요.

0.8.0

0.7.2: 같은 이름의 노트도 모두 검색

공개 2라운드 문서 20,000개에서 상위 2개 결과에 정답이 포함된 검증 질문은 270/1,011개에서 537/1,011개로 늘었습니다. 26.71%에서 53.12%로 26.41퍼센트포인트 상승했으며, 문항별로 274개가 개선되고 7개가 후퇴했습니다.

이미 색인되던 정답의 개발 묶음은 231/405개에서 224/405개로 감소했습니다. 일부 통계 묶음에 독립 출처가 하나뿐이라 사전 등록한 출처 신뢰구간을 계산할 수 없었습니다. 소유자는 이 조건을 명시적으로 면제하고 문항별 비교 근거에 따라 출시했습니다. 해당 조건을 통과했다는 뜻은 아닙니다. 기존 질문을 재사용했고 대체 정답 검토도 완전하지 않습니다.

과거 결과와 한계 읽기 ↗

인계와 라벨도 컨텍스트를 사용합니다

Windows 형식 키를 쓴 인계 픽스처는 추정 163 → 919토큰(+756), 별도의 라벨 픽스처는 1,052 → 1,076토큰(+24)으로 늘었습니다. 모델 토크나이저가 아닌 ceil(UTF-8 바이트 / 4) 추정입니다. 서로 다른 픽스처이므로 보편적인 총비용으로 더하면 안 됩니다.

선택형 검색에도 비용과 손실이 있습니다

의미 검색은 선택 기능이며 권장 기본값이 아닙니다. 일부 테스트 구간에서 코어보다 낮은 결과를 냈습니다. Linux 재실행의 설치 크기는 0.38 → 80.24 MB였고, 원본·압축 모델 파일 669.1 MB는 별도입니다. 최대 색인 메모리 증가분 163 MB는 150 MB 예산을 넘었습니다. 서비스 수준 보장이 아닙니다.

호스트가 작성하는 질의 확장은 검색마다 약 115–200 출력 토큰과 약 두 배의 순위 계산 시간을 씁니다. 이전 토크나이저 실험은 일반적인 한국어 검색 개선을 입증하지 못했습니다. 위의 별도 0.7.2 결과는 색인 수정에 대한 측정이며, 답변 정확도나 보편적인 다국어 지원의 증거는 아닙니다.

03 / 지금 쓰는 에이전트와 연결

하나의 저장소, 여러 연결 방식.

저장소는 로컬에 둡니다. 문서화된 어댑터를 선택하거나 Python API를 직접 에이전트에 연결하세요.

MCP 클라이언트

선택형 stdio 서버로 코딩 에이전트, 데스크톱 어시스턴트, 에디터 등 MCP 클라이언트를 연결합니다. 설정 가이드가 모든 IDE를 실제 실행·검증했다는 뜻은 아닙니다.

클라이언트별 설정 선택하기 ↗

Hermes

외부 메모리 제공자는 Hermes 프로필별 별도 저장소에 로컬 Markdown을 씁니다. 세션 종료·압축 전의 범위별 인계 캡처는 선택 기능입니다. 0.9.0부터 birkin_memory_forget과 birkin_memory_restore로 노트를 보관하고 되돌릴 수 있으며, confirm=true가 아니면 미리보기만 하고 아무것도 지우지 않습니다.

Hermes 제공자 설정하기 ↗

omo

MCP 도구로 검색하고 시작 문서를 완전히 읽습니다. 체크포인트를 명시적으로 캡처한 뒤 같은 프로젝트·작업 키로 재개하세요. 이 생명주기는 호출자가 관리합니다.

04 / 평범한 파일로 시작

설치하고, 미리 보고, 적용하세요.

Python 3.10 이상이 필요합니다. 코어는 모델·API 키·런타임 의존성 없이 노트를 저장하고 검색합니다.

코어 설치

pip install birkin-mnemosyne==0.9.0

mnemosyne init --vault my_vault
mnemosyne init --vault my_vault --apply

첫 init 명령은 읽기 전용 미리보기입니다. 계획을 확인한 뒤 적용하세요. --vault가 없으면 MNEMOSYNE_VAULT에 지정한 폴더를 쓰고, 그 값도 없으면 현재 폴더를 사용합니다.

PyPI에서 패키지 보기 ↗

MCP 클라이언트 연결

uvx --from "birkin-mnemosyne[mcp]==0.9.0" \
  mnemosyne-mcp --vault ~/mnemosyne

MCP 추가 패키지는 처음 실행할 때 공식 SDK를 내려받습니다. 클라이언트에 이 stdio 명령을 설정하세요. 같은 저장소를 지정하면 클라이언트끼리 기억을 공유합니다.
